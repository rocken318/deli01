# 案内表＝統合オペレーションコンソール 設計 — 2026-09-02

電話で商売を回す中心画面を「案内表」に統合する。従来バラバラだった **受付（オーダーエントリ）＋配車＋出勤の実績＋会計** を1つのコンソールに集約し、独立した「受付表」画面を畳む。実運用シート（[[deli01-real-ops-sheets]]）と D(QR出退勤)・B(キャスト自入力) の上に載る。

視覚コンパニオンで v4〜v15 まで反復して合意した設計（[[deli01-annai-reception-brainstorm]]）。

## 目的
- 電話しながら「今すぐ/早く行ける子」を一目で見つけ、**その場で予約まで**できる。
- 各セラピストの一日（終わった仕事・次案内可能・これからの仕事）が1行で分かる。
- 空き窓（何分まで入れられるか）が見えるので、電話中に即断できる。

## 情報設計（1コンソール・3タブ）
1. **案内表タブ**（本設計の主役 / 新規）：人ごと・次案内可能の早い順。
2. **時系列/進行タブ**：**既存の配車ボード `/admin/dispatch-board` を据える**（新規ページは作らない）。時刻順に迎え/出発/IN/OUT/遅延・退出未記録アラート。
3. **日次会計タブ**：バックログG（日次締め＝確認用/SGS確認用の形）。本設計では枠だけ。

案内表タブ内の操作は**別ページに飛ばない**（開く/閉じる）。例外は予約カード→予約詳細、名前→セラピスト詳細（既存ページ遷移）。

## 案内表タブ：レイアウト（v13 で合意）
- 1行=1セラピスト。**次案内可能時間の早い順に上からソート**（今すぐ→時刻順）。当日欠勤は記録して非表示（人数カウンタのみ）。上がりは太線の下段。
- **中央固定の「次案内可能」カード**（全員が縦に揃う"背骨"・特大 等幅・緑枠）。下に**「〜HH:MMまで／空きN分」**。
- **左＝終わった仕事**（右寄せ・横並びの小カード：時刻・金額）／**右＝これからの仕事**（左寄せ・横並びの小カード：時刻・出発時刻）。多い時は各サイド横スクロール。
- 状態＋色（spec 12-2）：未着手(灰)→LINE送信済(黄)→出勤確定(緑)／遅刻(橙・**手動フラグ**)／接客中(赤)／待機中(緑)／上がり(灰)／当日欠勤(赤・非表示)。
- **名前クリック**→その子の今日の予定＋これまでの売上（既存 `/admin/therapists/[slug]`）。
- **予約カード（過去/未来）クリック**→予約詳細（既存 予約詳細ページ）。
- **上がりに「清算」ボタン**→清算パネル（下記）。

### 次案内可能ウィンドウの計算（純関数・要テスト）
`computeAvailableWindow(now, todayReservations[], shift?, buffers)`:
- 開始 = `max(now, 最後の done 予約の free_at)` ＋ 移動（既定15分・全員同一エリア）。予約が無く出勤済なら「今すぐ」。未確定(LINE/未着手)は出勤予定時刻＋移動の見込み。
- 上限 = 次の confirmed/未来予約の `depart_at`（= 次予約 start − 移動 − 準備）。無ければ「上限なし（シフト終了まで）」。
- `空きN分 = 上限 − 開始`。負なら空きなし。
- **buffers（準備/移動/上がりバッファ）は編集可＝その日だけの一時上書き**（その子既定・全体既定にはしない）。既存の travel_buffers/area 移動時間を初期値に、当日オーバーライドを別途保持。

## 案内表タブ：インライン予約ポップ（v11〜13 で合意）
行クリックで**その行の下に横長ポップ**が開く（閉じれば元の板）。既存 OrderEntryForm の料金・顧客・ホテル検索ロジックを流用。
- **入力**: 顧客電話(検索)・名前・コース・開始(空き窓に既定)・指名・場所/ホテル(検索)。
- **オプションはチェックボックス**（前立腺/キス/タッチ/デンマ/フェラ/ヌード＝金額つき）。
- **延長はプルダウン**（なし/15/30/45/60分＝分→金額）。
- **ホテル名→交通費を自動**（hotel→area→交通費。入り方(1F外迎え等)も自動で備考へ）。
- **★備考欄（必須・目立たせる）**: 服装・ホテルの入り方・移動確約など自由記述。
- **総額を大きく常時表示**（右パネル・金色）＝電話で伝えるため。`総額 = コース＋指名＋OP＋延長＋交通費 − 割引`。入力変更で即再計算（純関数 `computeOrderTotal` を切り出し・要テスト）。
- 「予約する」で reservations に作成（既存の仮押さえ/exclusion を尊重）→カードに反映。

## 予約ごとのチェックポイント（P2）
受付表の進行管理を予約カード/詳細に載せる。既存 status(confirmed→enroute→in_service→done)＋時刻に加え、新規チェックポイント列を reservations に追加：
- `confirm_call_at`（確認電話済）・`entry_call_at`（入室電話受）。入室=arrived/service_started、退出=done は既存を流用。
- 遅刻は attendances 側の**手動フラグ**（`late` 手動）。
- カード決済フラグ `is_card_payment`＋`payment_url`（**決済URLは配線のみ・v1は手動/空。オンライン決済は spec「やらないこと」＝決済プロバイダ導入後に自動発行。実処理は作らない＝金銭・要発注者**）。

## 清算パネル（Q1 の回答・P2）
上がりの「清算」から開く**パネル（別ページではない）**。本日の予約ごとに：
- `決済(現金/カード)`・`カード決済`チェック→`決済URL`欄・`回収額`入力・**照合（総額と一致✓／差額）**。
- 「照合OKで清算を締める」→ **誰が・いつ・照合結果を追記**（会計台帳＝追記専用の思想）。差額はメモ必須。締めると案内表の「✔会計済」が立つ。
- 集金確認 = `collected_amount` + `reconciled_by` + `reconciled_at`（新規・追記）。

## 段階実装（1フェーズ=1PR）
- **P1a（最初のPR）**: 案内表タブ = **板の読み取りビュー**。per-therapist 集約クエリ（RLS）＋純関数 `computeAvailableWindow`＋v13レイアウト（早い順・中央固定・左右横並び・状態・名前/カードのリンク）。**まだ予約作成はしない**。当日データは seed-demo の当日タイムラインで検証。
- **P1b**: インライン予約ポップ＋`computeOrderTotal`＋ホテル→交通費＋延長プルダウン＋備考＋総額。作成は既存予約作成ロジック流用。
- **P2**: チェックポイント（確認電話/入室電話）＋清算パネル（集金照合・カード決済/決済URL配線）。
- **時系列/進行タブ** = 既存配車ボードをタブに載せる（薄い統合作業）。
- **日次会計タブ** = バックログG（別設計）。

## 非目的 / 注意
- **オンライン決済の実処理は作らない**（spec「やらないこと」・現地決済から）。決済URLはプロバイダ導入後の配線用プレースホルダ。
- LINE 自動送信は作らない（テキスト生成まで）。
- 位置情報は扱わない（D と同方針）。

## テスト方針
- 純関数：`computeAvailableWindow`（開始/上限/空き分・予約なし・done複数・未確定見込み・上限なし・buffer上書き）、`computeOrderTotal`（コース＋指名＋OP＋延長＋交通費−割引・境界）。
- 統合（実Postgres）：板クエリが per-therapist の done/upcoming/next-available を正しく返す・RLS（owner/admin/reception 閲覧）・seed-demo 当日タイムラインで期待値。
- 禁止事項 grep：any/直書き日本語(管理側OK)/金額小数(整数円)/日時文字列計算(date-fns-tz)/jsonb直書き。
