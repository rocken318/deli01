# 空き枠アルゴリズムの説明 — availability.md

このシステムの核。**「移動を挟んで次の予約が入るか」を判定する空き枠算出エンジン**の説明（spec 5章 / L1162）。運用者が仕様を理解できる粒度で。設計ノートは [booking-holds.md](./booking-holds.md)・[areas-travel.md](./areas-travel.md)。

## 1件の予約は「移動 → 施術 → 移動」の3ブロック

```
   depart_at          start_at        end_at         free_at
      │  ── 移動(到着) ──  │ ── 施術(L) ── │ ── 移動(撤収) ── │
      ↑ 前の場所を出る    ↑ 案内開始      ↑ 施術終了     ↑ 次へ動ける
```

- **占有区間は `depart_at 〜 free_at`**（施術時間だけでなく前後の移動も塞ぐ）。配車ボードでもこの3ブロックで見える。
- `L` = コース時間 ＋ 選択オプションの時間の合計。オプションで施術が延びると `end_at`・`free_at` が後ろへ動く。

## 二重予約は DB が防ぐ（exclusion 制約）

同じセラピストの占有区間（depart_at〜free_at）が重なる予約は、アプリではなく **DB の排他制約（exclusion）** が弾く。同時アクセスでも片方だけが成功する。キャンセル／無断キャンセルは占有から外れ、枠が空く。

## 移動時間の出し方（徒歩 or 車）

- **徒歩圏（距離が閾値以内）は徒歩**。超えたら**車**（セラピストが車不可なら「案内不可」）。閾値ちょうどは徒歩圏。
- 徒歩は PostGIS の距離から毎回計算。車は**エリア間の移動時間マトリクス × 時間帯係数**（渋滞を反映）。Google Maps キーが無い間は手動の暫定値。
- **バッファ**（到着・駐車・施術前後）を移動に加える。**ホテルは館内移動時間（extra_minutes）を到着側に加算**。都心は駐車バッファ大、など CMS でエリア別に上書き可能。

## 空き枠の判定（1件入るか）

ある gap（直前の予約 P と直後の予約 N の間）に新しい施術が入るかは、
**「P を出て移動 → 到着 → 施術（L）→ 撤収移動して N に間に合う」**が成り立つかで決まる。成り立つ開始可能時刻だけを 15 分グリッドで案内する。**成り立たない枠は出さない（嘘の枠を出さない）**。

## 当日延長の可否

施術中にオプション追加（延長）で `free_at` が伸び、**後続予約の depart_at を超えると「間に合わない」ので追加を拒否**する。管理者は理由つきで上書きできるが、物理的な二重予約は exclusion が最終的に弾く。

## 最短案内

公開側の「最短 HH:MM から案内可能」は、住所（またはエリア代表点）を前提にエンジンで再計算した最短の開始可能時刻。古い枠を出さないため force-dynamic（毎回計算）。
