# 電話受付の操作手順 — order-entry.md

新人が読んで即使えることを目標にした、電話受付（`/admin/orders`）の手順。関連: [着信ポップ](#着信ポップ)・[電話確認](#電話確認)・[配車テキスト](#配車テキスト)。

## 1. 電話を受ける

- （CTI 導入時）着信すると `/admin/cti`「着信ポップ」に電話番号と顧客名が出る。既存顧客なら名前が分かる。
- 受付画面 `/admin/orders` で **電話番号を入力**すると、既存顧客なら**氏名・住所・お好み・NG が自動補完**される。初めての番号は新規として入力。

## 2. 条件を聞いて空き枠を出す

- **日付・エリア（またはホテル）・コース・オプション**を選ぶ。ホテルが未登録なら**その場で仮登録**（電話を止めない）。
- 「候補セラピスト」から、**実際に案内できる枠**が出る（移動を挟んで間に合う枠だけ。仕組みは [availability.md](./availability.md)）。誰でもよければ候補から選ぶ（割当は人間が決める）。
- 枠が無ければ**無理に入れない**（嘘の枠を出さない）。どうしても入れる必要があれば**枠外予約（override）**＝理由必須・監査に残る。

## 3. 確定する

- 顧客名・行き先（自宅／ホテル＋部屋番号）・お好みを入力して確定。
- **電話注文は保存時に自動で「電話確認済み」**になる（受付が本人と話しているため）。
- 金額はサーバ側で再計算される（コース＋オプション＋指名料＋交通費＋深夜加算）。表示は参考値。
- **ポイント**: 電話番号で貯まる／使える。確定後に予約詳細からポイント利用を記録できる（会計への値引き反映は会計側）。

## 4. 成立しなかったら（不成立ログ）

- 条件が合わず注文にならなかったら **「不成立」を記録**（理由: 時間／エリア外／指名不可／料金／その他）。**理由なしでは保存できない**。どこで注文を落としているかが数字になる（集計・需要ヒートマップに反映）。

## 着信ポップ

`/admin/cti`（下地）: 直近の着信を新しい順に表示。電話番号で顧客名を引き当てる。リアルタイム表示・回線契約は事業判断後に配線。

## 電話確認

- **Web 予約**は確定後も「電話確認待ち」。受付が電話で本人・住所・時間を確認し、**チェックを付けた予約だけが「確認済み」**になる（`/admin/phone-confirm`）。
- **確認が済むまでセラピストへ確定情報（住所入り）を送れない。** 打診（個人情報なし）は確認前でも可。
- 3回不通なら運営判断でキャンセルにできる（記録が残る）。

## 配車テキスト

`/admin/dispatch`: セラピストへ送るテキストをワンタップでコピー。
- **打診用**（住所・電話番号を含まない＝エリア・時間・コース・バック額のみ）
- **確定用**（住所・部屋番号・顧客名・お好み。**電話確認済みの予約だけ**生成可）
- コピーすると送信ログ（誰の情報を・いつ・誰に）が残る。
